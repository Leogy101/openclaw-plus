# Security boundaries

OpenClaw+ is an unofficial local frontend. OpenClaw remains responsible for gateway authentication, permissions, approvals, agent execution and terminal lifecycle. The app is not an additional sandbox for a gateway-hosted shell.

The current adapter accepts only the configured local loopback gateway over local HTTP/WebSocket transport. The supported authentication modes are token and password; TLS and remote endpoints are not supported. The renderer has no Node access or direct gateway connection; native operations pass through validated main-process handlers. Message sends, approval decisions, configuration saves and terminal starts require explicit user actions. Gateway policy still applies to those actions.

Terminal output is untrusted content. Selecting **Add selection to message** prepares a draft; only **Send** shares it with the selected conversation. Configuration changes may restart the gateway. An unconfirmed operation must be reviewed before retrying.

Execution permission changes bind to the selected physical session and the reviewed permission mode, plus the lifecycle revision when OpenClaw supplies one. Full Access requires a separate acknowledgement and native administrator authorization; Default inherits configured policy and does not guarantee restricted access. A submitted change with an uncertain outcome requires a fresh read before another attempt.

Read Aloud sends selected report prose to the gateway’s configured speech provider only after an explicit click. Dictate and Talk request macOS microphone access only after choosing a mode. Audio passes through the configured local gateway connection; gateway credentials remain outside the renderer. Dictation prepares a draft. Live Talk can initiate native agent work under existing OpenClaw policy and approvals. Audio is bounded in memory, never automatically replayed after a disconnect, and not saved in an app recording database. Provider and OpenClaw retention policies still apply.

Only the trusted main application frame can request microphone capture during a short explicit capture grant. Camera and other web permissions remain denied. The renderer can load only bundled resources and validated local playback audio, with no direct provider or external network access. Leaving the owning conversation, hiding or minimizing the app, disconnecting, or quitting stops microphone capture; closing only the Voice options dialog does not end an active call. The visible Stop/Cancel controls remain available. Supported live-session detach preserves already accepted agent work, while an explicit Stop requests the native stop behavior.

## Models and local state

The Models catalog reads prepared metadata and installed provider setup declarations. It has no discovery, authentication-refresh, admission or live task-routing operation. Native catalog handling can still perform OpenClaw’s normal login-state bookkeeping. A displayed provider or model is not proof of successful authentication, inference or permission to use it in a session. Opening provider setup hands off to the original local OpenClaw interface; any changes there are separate native actions.

Models Checks delegates research, bounded profiling, scoring, bios and routing previews to the independently installed GCB package. Its executable is selected through a native file chooser, never a renderer-supplied command. Connecting an executable runs trusted local software; select only your reviewed GCB installation. Fixed argument arrays, bounded output, a restricted environment and exact IPC operations separate this process from the renderer. GCB remains a trusted local package, not a sandbox for arbitrary installed code.

Offline demonstrations use GCB's fictional backend and are explicitly labeled synthetic. OpenClaw-host execution requires an imported nonsecret reviewed host snapshot, a matching fresh native catalog, the existing GCB subscription bridge, an exact benchmark review and explicit usage authorization. Authentication stays in OpenClaw. No API keys, account switching, bridge installation, permission changes, agent reassignment or Gateway restart are performed. The native host may not enforce an output-token hint or expose actual billed cost and hidden provider retries; the review shows those limits. The user authorizes bounded host invocations, not a guaranteed monetary cap. Every resume requires a new review; GCB retains cumulative plan limits and prevents replay of uncertain completions.

Local Ollama smoke checks use GCB's existing direct loopback adapter. The main process accepts only a native model reference, verifies current local availability and selection policy, and reads the already configured `127.0.0.1` endpoint from the bound native configuration. It refuses remote URLs, header-authenticated routes, cloud targets and attributed agent execution contexts. It neither resolves nor forwards credentials. Research reads metadata only. An explicit usage review grants at most one local inference attempt with the exact researched `think:false` setting and fixed request limits; GCB rechecks artifact identity before dispatch. The model can cold-load and remain resident. Cancellation is not proof of server termination; uncertain results cannot be replayed automatically.

GCB SQLite evidence and app connection/index records live separately from the registration registry in the private `GCB` support directory. They are local, unencrypted data and can reveal model choices, nonsecret host snapshot metadata and fixture results. Cancellation requests do not prove provider termination. Pausing stops after the current cell, while interruption or cancellation can leave unknown results requiring review. Routing recommendations are explainable previews only; unsupported native pre-inference enforcement remains inactive. See [GCB integration](GCB_INTEGRATION.md) for setup and verification.

Recorded responses are loaded only when the user opens their details. The main process reads GCB's existing evidence command for the selected registered plan, validates its identity and returns bounded allowlisted fields. Response text is escaped, capped and kept separate from expected scoring criteria; missing output is never inferred from a passing score. The desktop does not duplicate the result store. Retained output may still contain sensitive information: review the visible contents before sharing screenshots or diagnostic exports. The current GCB contract retains parsed structured fixture output, not arbitrary original text or hidden thinking.

Personal model references and the last sanitized catalog snapshot are stored as owner-only JSON in the app’s `ModelManager` support subdirectory, with a previous snapshot for recovery. This data is not encrypted and may reveal model/provider choices to processes running as the same user. The registry contains no gateway credentials or qualification/admission records. Corrupt or externally changed storage becomes read-only rather than being silently replaced. Unsent drafts and attachment selections are held in memory. Do not share app profiles or diagnostic evidence without reviewing their contents.

## Reporting a concern

Do not put credentials, configuration dumps, private conversations or sensitive terminal output in a public issue. Use synthetic data and the smallest reproduction that demonstrates the problem.

If the repository offers GitHub private vulnerability reporting, use that channel for security-sensitive details. Otherwise, ask the maintainer for a private reporting channel without disclosing the sensitive details publicly. No dedicated security contact or response-time commitment is established by this document.

Local packages are ad-hoc signed, not Developer ID signed or notarized. Automatic updates and remote gateway support are not provided by this release.
